# 基论港辩论教练·公开测试

这是 `jilungang-debate-coach` 1.2.1 的公开测试版。如果你手上正好有一道辩题、一篇写不顺的稿，或一份不知道怎样处理的对方材料，可以直接拿来试。

我不期待它替你包办整场比赛。我更在意的是，它能不能先找到你当下真正卡住的地方，再把这一步做完。

## 先拿一个真问题来试

还没选边时，可以让它先中立分析。已经有持方时，可以让它建立立论或写一辩稿。如果你已经写了一半，可以只让它找出最影响结论的那处问题。有对方材料时，再继续做攻防、质询或总结。

事实型辩题也可以拿来，但请告诉它你需要资料查询。这时的重点不是找几条看起来支持己方的网页，而是先说清楚到底要证明什么。

## 安装

1. 打开本公开仓库的 Releases，下载固定版本的 Source code；也可以克隆仓库，但不要把浮动的 `main` 当成可复现版本。
2. 把完整的 `jilungang-debate-coach` 文件夹复制到 `~/.codex/skills/`。最终路径应当是 `~/.codex/skills/jilungang-debate-coach/SKILL.md`，不要多套一层仓库目录。
3. 完全退出并重新打开 Codex，再用下面任意一句开始。

## 可以这样开始

```text
使用 $jilungang-debate-coach 分析辩题：只分享快乐不分担痛苦的浅度友谊，是现代社交的进步还是退步。先保持中立。
```

```text
我持正方：金钱是万恶之源。写一篇一辩稿，这一轮不用加攻防。
```

```text
帮我看看下面这篇稿最早从哪里断了。只改必要的段落，保留我的表达。
```

```text
下面是对方一辩稿。请只根据他们真正说过的内容设计质询，预备回答写成条件分支。
```

```text
这是一个事实型辩题。先列出需要证明的事实，再查资料，说明每份资料能证明什么、不能证明什么。
```

## 我希望你看到的不是一张流程表

拿“浅度友谊是现代社交的进步还是退步”来说，一次像样的中立分析，不应该只是罗列正反理由。它需要先问：我们所谓的社交进步，只看个人选择更自由，还是也要看一段关系能不能承担风险？

接下来，两种立场要处理同一种友谊、同一类人和同一个时间尺度。最后再看哪条连接最需要证明，什么事实会让当前判断改变。

如果你要的只是中立分析，结果就应该停在这里，不替你选边，也不顺手附送一辩稿和攻防表。

## 需要查资料时

稳定知识优先查权威教材、学术手册、完整专著和机构性资料。快速变化的现实问题，先追官方原始文件，再用经过核对的权威媒体补足时间线和现场信息。中国议题优先核对境内来源，国际资料用来补充。

单篇论文、学位论文、系统综述、Meta 分析、民间调查、利益相关机构报告、网络文章和自媒体默认都是高风险资料，不推荐未经审查就拿来做核心论据。这是风险预警，不是文献黑名单。

如果任务使用了快速变化的名单、许可或热点事件，结果应该标出“截至某日核验”。

## 它还不稳定的地方

这仍然是公开测试版。有时它会把问题说得过于抽象，有时对资料过于保守，也可能找对了问题，却没有把结果变成可以在赛场上说出口的话。

这些失败比一句“不好用”更有价值。如果遇到了，请尽量保留脱敏后的最小复现输入、实际输出的必要片段和你希望它怎样做。

## 这个项目从哪里来

林正疆学长的公开辩论视频课程是我直接的辩论启蒙，他关于不让知识、思考和表达成为奢侈品的微博分享，也给了项目很重要的启发。张子龙学长长期公开的大量文章和思考，则直接启发了许多设计思路。

## 反馈、更新与授权

一般功能问题、表达建议和文档问题，请使用[公开测试反馈模板](https://github.com/jilungang-lab/jilungang-debate-coach-beta/issues/new?template=skill-feedback.md)。公开仓库中的 Issue 任何人都可查看，它不是一对一私信；提交 Issue 需要登录 GitHub。只提交脱敏后的最小复现，不要上传比赛密件、完整未公开稿件、个人信息，或无权分享的书籍和论文全文。

无法脱敏的问题、隐私问题和版权异议，请改用小红书私信。具体账号、提交顺序、误发处置和处理约定见 [SUPPORT.md](SUPPORT.md)。如果无法判断内容是否敏感，默认先私信问题摘要。

更新时，先完全退出 Codex，将旧的 `jilungang-debate-coach` 目录移出作为备份或删除，再复制全新的六文件目录；核对文件清单后重新打开 Codex。不要直接覆盖旧目录，以免遗留废弃文件。卸载时，退出 Codex，删除 `~/.codex/skills/jilungang-debate-coach` 文件夹，然后重新打开。

安装前请记录 [VERSION](VERSION)、下载标签和提交号，并优先从固定 Release 或标签下载，不以浮动的 `main` 作为可复现版本。详细的脱敏反馈字段见 [FEEDBACK.md](FEEDBACK.md)。
